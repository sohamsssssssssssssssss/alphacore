# Project Verdict: NIFTY Large-Cap MA Crossover Walk-Forward Study

## Summary

This project tested a simple 50/200-day moving-average crossover strategy on 15 NIFTY 50 large-cap stocks (daily data, 2015–2024) using a no-lookahead walk-forward pipeline with realistic transaction costs (0.1% per side + slippage). The cross-ticker mean out-of-sample Sharpe was **0.04** — statistically indistinguishable from zero. On RELIANCE.NS (the single-ticker deep dive), walk-forward Sharpe was **−0.24** with only **3/8 folds profitable**. A permutation test on the 8/15 tickers that ended up nominally positive returned **p = 0.990**, confirming the split is entirely consistent with noise. No statistically distinguishable edge exists after costs.

---

## What Was Built (Methodology First)

The point of this project was not "did I find alpha" but "did I build a methodology that can't lie to itself."

- **No-lookahead enforcement** — Unit tests verify the backtester never peeks at future bars; signal computation is strictly `shift(1)`-aligned.
- **Realistic cost/slippage model** — 10 bps per side commission + 5 bps slippage, applied on every fill; costs dominate gross PnL.
- **Walk-forward validation (not full-history backtest)** — Expanding-window retraining: train on years 1–N, test on year N+1, repeat. 8 folds per ticker.
- **Multi-ticker generalization check** — Same pipeline run across 15 liquid NIFTY names; results aggregated at the ticker level, not pooled.
- **Permutation-based noise test** — Null distribution generated by shuffling ticker labels 10,000×; tests whether the "8/15 positive" split exceeds chance.

## Why the Strategy Doesn't Work

After realistic transaction costs, a naive 50/200 MA crossover does not clear the bar on liquid NSE large caps. This is the well-known, expected result for simple trend-following without additional filters (volatility regime detection, adaptive lookback windows, trend-strength confirmation). The strategy whipsaws in sideways markets and gives back too much on reversals. This section states the observed outcome, not an untested hypothesis about fixes.

---

## What This Demonstrates

The value of this project is the **rigor of the testing pipeline**, which would catch a false-positive result just as reliably as it caught this true-negative one. A project that found a fake edge because it skipped walk-forward validation, ran on one ticker, or ignored transaction costs would look better superficially and be worse in substance. The methodology is the artifact; the negative result is the validation that the methodology works.

---

## Honest Limitations

- **Only one signal family tested** — RSI and momentum signals exist in the codebase but were not walk-forward validated in this write-up.
- **No regime filters or adaptive parameters** — Fixed 50/200 windows throughout; no volatility-dependent window scaling or trend-strength gating.
- **Daily frequency, single-asset only** — No portfolio construction, no cross-sectional ranking (e.g., long top-decile momentum / short bottom-decile), no intraday or higher-frequency signals.
- **Permutation test scope** — The p=0.990 test checks noise in the *ticker-level split*, not whether some entirely different signal could find real edge on this data.

---

## Natural Next Steps

- Run the **RSI and momentum signals** through the identical walk-forward + permutation-noise pipeline.
- Add a **volatility regime filter** to MA crossover (e.g., only take signals when 20-day realized vol is in the lower two quartiles) and re-test.
- Extend to **cross-sectional ranking** (long top-decile momentum, short bottom-decile) rather than single-asset absolute signals, with the same cost model and walk-forward discipline.
